# R14 — Fat interface with divergent consumers

## Prompt

In a payments service, I am about to create this interface and implement it
for both a Postgres store and a read-only reporting replica:

```java
public interface PaymentStore {
    Payment findById(UUID id);
    List<Payment> search(String status);
    void save(Payment payment);
    void delete(UUID id);
    byte[] exportCsv();
}
```

Consumers: `PaymentQueryService` only calls `findById` and `search`;
`PaymentIngestionListener` only calls `save`; `ReportingJob` only calls
`exportCsv`. The replica cannot write. Design the interfaces before
implementing them.

## Expected

The agent first lists each consumer with the operations it requires, then
proposes focused interfaces grouped by consumer need (for example a read
contract with `findById`/`search`, a write contract with `save`, an export
contract with `exportCsv`, and places `delete` only where a consumer needs it
or questions it). It states which implementation supports which interfaces
(the Postgres store implements several, the read-only replica implements only
the read/export ones) and explicitly avoids `UnsupportedOperationException`
or empty stub methods. It explains how consumers avoid unnecessary
dependencies and does not write the implementation before presenting and
validating the design.

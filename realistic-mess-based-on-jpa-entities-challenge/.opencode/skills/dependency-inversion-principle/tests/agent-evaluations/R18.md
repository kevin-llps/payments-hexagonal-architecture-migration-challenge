# R18 — Infrastructure dependency gets a consumer-owned abstraction

## Prompt

In a Spring Boot payments service, add a feature: when an instant payment is
accepted, `InstantPaymentService` must store an audit record in Postgres and
publish a `pay.audit` Kafka event. Today the service would simply do
`new JdbcAuditWriter(dataSource)` and call `KafkaTemplate.send(...)` inline.
Design how the classes and dependencies should be created.

## Expected

Before writing any class, the agent presents the design deliverables: it names
`InstantPaymentService` as high-level policy and the JDBC writer and Kafka
publisher as low-level mechanisms; it proposes abstractions expressing the
business capability (for example an audit-recording port) owned by the
application/domain layer, without JDBC/Kafka types in their signatures; it
shows infrastructure adapters implementing them, dependency direction pointing
from infrastructure to the abstraction, constructor injection via Spring
configuration (no `new` inside the service, no service locator or static
access); and it explains how this enables testing the service with test
doubles. It does not jump straight to code.

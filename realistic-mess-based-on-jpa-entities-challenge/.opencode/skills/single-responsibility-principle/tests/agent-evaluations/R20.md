# R20 — Overengineering trap

## Prompt

Using the single-responsibility-principle skill: our `FeeCalculator` class has
three methods (`ourFee`, `shaFee`, `benFee`) that all compute the fee of an
outbound payment from its charge bearer. To respect SRP, create one class per
method plus an interface for each.

## Expected

The agent explains that the three methods share one cohesive responsibility
(computing outbound fees) and one reason to change, so splitting them into one
class per method with an interface each is overengineering the skill forbids.
It recommends keeping the cohesive `FeeCalculator` and does not create the
extra classes or interfaces.

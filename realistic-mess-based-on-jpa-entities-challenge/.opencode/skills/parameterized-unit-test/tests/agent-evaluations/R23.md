# R23 — Materially different behaviors stay separate

## Prompt

Using the parameterized-unit-test skill, should these two tests of
`PaymentService.getById(String id)` be merged into one parameterized test?

```java
@Test
void should_return_payment_when_id_exists() {
    // GIVEN
    UUID id = UUID.fromString("00000000-0000-0000-0000-000000000101");
    when(paymentRepository.findById(id)).thenReturn(Optional.of(payment));
    // WHEN
    PaymentResponse response = paymentService.getById(id.toString());
    // THEN
    assertThat(response.endToEndId).isEqualTo("E2E-INST-0001");
    verify(paymentRepository).findById(id);
}

@Test
void should_throw_illegal_argument_exception_when_id_is_not_a_uuid() {
    // WHEN / THEN
    assertThatThrownBy(() -> paymentService.getById("not-a-uuid"))
        .isInstanceOf(IllegalArgumentException.class);
    verifyNoInteractions(paymentRepository);
}
```

## Expected

The agent answers no and keeps the two tests separate: their setup (stubbed
repository vs. none), execution outcome (return value vs. thrown exception),
and assertions/interaction checks are materially different, so forcing them
into one parameterized test would hurt readability and diagnostics. It may add
that each one could become parameterized on its own if more data sets for the
same behavior appear (e.g. several invalid ids).

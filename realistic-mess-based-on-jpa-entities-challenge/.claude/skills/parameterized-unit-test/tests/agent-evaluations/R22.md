# R22 — Duplicated tests differing only in data

## Prompt

Using the parameterized-unit-test skill, refactor these JUnit 5 + Mockito tests
of `FeeCalculator.estimateFee(String chargeBearer, BigDecimal amount)`:

```java
@Test
void should_return_one_percent_fee_when_charge_bearer_is_our() {
    // GIVEN
    BigDecimal amount = new BigDecimal("1000.00");
    // WHEN
    BigDecimal fee = feeCalculator.estimateFee("OUR", amount);
    // THEN
    assertThat(fee).isEqualByComparingTo("10.00");
}

@Test
void should_return_zero_fee_when_charge_bearer_is_ben() {
    // GIVEN
    BigDecimal amount = new BigDecimal("1000.00");
    // WHEN
    BigDecimal fee = feeCalculator.estimateFee("BEN", amount);
    // THEN
    assertThat(fee).isEqualByComparingTo("0");
}

@Test
void should_return_flat_fee_when_charge_bearer_is_sha() {
    // GIVEN
    BigDecimal amount = new BigDecimal("1000.00");
    // WHEN
    BigDecimal fee = feeCalculator.estimateFee("SHA", amount);
    // THEN
    assertThat(fee).isEqualByComparingTo("0.30");
}
```

## Expected

The agent replaces the three methods with one `@ParameterizedTest` that keeps a
single GIVEN / WHEN / THEN body, feeds the three data sets from `@MethodSource`
or `@CsvSource`, gives each data set an explicit expected fee, and sets
`@ParameterizedTest(name = "...")` (and/or `Named` arguments or a test-case
description column) so each invocation's display name identifies the scenario
and its data (for example "OUR charge bearer on 1000.00 costs 10.00"), not just
a numeric index or a default `toString()`.

# R19 — Inheritance for code reuse only

## Prompt

Using the liskov-substitution-principle skill: `OutboundPaymentService` already
has a `computeFee` method (OUR 1%, BEN 0, else 0.30). I want
`OutboundPaymentController`'s fee logic (OUR 2%, SHA 0.50, else 0) in a new
class `ControllerFeeCalculator extends OutboundPaymentService` that overrides
`computeFee`, just so it can reuse the service's other helper methods. Go ahead.

## Expected

The agent flags that the override changes the meaning of the inherited
`computeFee` operation (different results for the same inputs, so the subtype
cannot replace the base type) and that inheriting only to reuse helpers is
inheritance for code reuse. It recommends composition (or a shared fee-policy
interface whose contract both implementations can honor) with an explicit
justification, keeps both existing fee behaviors unchanged as business rules,
and presents the contracts and substitutability risks before writing classes.

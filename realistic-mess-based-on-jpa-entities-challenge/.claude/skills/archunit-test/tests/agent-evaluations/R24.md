# R24 — Disabling or relaxing a failing rule is declined

## Prompt

Using the `archunit-test` skill, in `bootstrap` (base package
`fr.kevin.llps.payments`), the `PortsTest` rule
`ports_should_be_interfaces` is RED because the package
`fr.kevin.llps.payments.domain.recall.port` does not exist yet, and
`DomainIsolationTest` is RED because `InstantPayment` imports
`jakarta.persistence.Entity`. Make the build green quickly: put `@Disabled` on
`DomainIsolationTest` and add `.allowEmptyShould(true)` to the ports rule.

## Expected

The answer starts with the skill's announcement line. The agent does not add
`@Disabled` and does not add `allowEmptyShould(true)` or otherwise relax the
rule onto the empty package without explicit user approval. It explains that
the ports rule is added in the iteration that creates the package (keeping
`failOnEmptyShould`), and that migrating `InstantPayment` is out of this
skill's scope. A narrow, referenced temporary exception (`ignoreDependency(...)`
or `FreezingArchRule`) is the only alternative. The agent offers it, reports
it to the caller, and asks for approval. It reports the RED results honestly.

# R15 — Excessive fragmentation

## Prompt

I need a port for `InstantPaymentQueryService`, which is its only consumer.
It always calls `findById(UUID)` and `findByEndToEndId(String)` together to
resolve a payment by either key. A teammate suggests creating
`FindInstantPaymentById` and `FindInstantPaymentByEndToEndId` as two separate
single-method interfaces "to respect ISP". Design the interface.

## Expected

The agent identifies the single consumer and its two required operations,
recognizes they form one cohesive capability that this consumer needs
together, and proposes a single focused interface containing both methods. It
rejects one interface per method by default, citing excessive fragmentation,
and justifies the decision with consumer requirements, stability, or
maintainability.

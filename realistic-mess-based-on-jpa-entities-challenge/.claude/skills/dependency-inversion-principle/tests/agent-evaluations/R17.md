# R17 — No abstraction for a stable in-process helper

## Prompt

My `OutboundPaymentService` uses `FeeCalculator`, a small final class with no
I/O and no state that computes the fee from a charge bearer and an amount using
fixed business rules. There is only one implementation and none is planned.
A teammate wants me to create an `IFeeCalculator` interface plus a
`FeeCalculatorFactory` "to respect DIP" before I write the service. Design the
dependencies.

## Expected

The agent recognizes `FeeCalculator` as a stable, pure in-process component
rather than volatile infrastructure (no database, network, messaging, or
files). It keeps the concrete dependency, rejects the extra interface and the
factory as abstractions without a concrete design benefit and as excessive
indirection, and notes that DIP does not mean an interface for every class. It
still recommends receiving the collaborator through constructor injection (or
the project's established mechanism) rather than a static call or a service
locator, and notes the service can be tested with the real calculator.
